The API

6 keyless endpoints. One of them is the whole engine.

CoinMarketCap publishes, per swap and with no key, the maker address, the block, the log index, the side and both amounts. Order the prints, join on the maker: a middleman has to print, so the row order alone names it. No mempool view, no MEV labels — and none needed.

finding 1 · CORS
3 headers sent

A keyless 200 carries Allow-Headers, Allow-Methods and Max-Age — and not Access-Control-Allow-Origin. The browser discards a body it already has. Every web tool on /public-api needs a proxy; this one's is /api/swaps, which also puts every visitor behind one IP.

finding 2 · the throttle
p50 1.5 s · p95 16.4 s

One keyless page, 8 iterations: most took about a second and a half; one sat through a 15 s backoff because the anonymous tier reports its per-IP limit as HTTP 500 as often as 429, with no Retry-After. The tool backs off 15 / 30 / 60 s and exits 75 when the quota is spent.

finding 3 · the price field
26 of 400 rows

q equals a1 / a0 on 374 of 400 PEPE rows; on 22 Uniswap v4 rows and 4 Uniswap v3 rows it is rounded to two significant figures, or zero. Invisible in a chart, fatal in a basis-point comparison — so the engine never reads q; it divides a1 by a0 itself.

8 dated, evidenced findings for the CoinMarketCap team — and what is worth protecting — in FEEDBACK.md↗ (opens in a new tab). Every endpoint the code calls is named above; tests/test_published_counts.py fails if one ever is not.

Questions a judge will ask

Honest limits.

Is this page live?

The table is rendered from a committed run, captured 2026-09-18 22:36:19 UTC, and says so on every number. The paste box is live: it runs the same engine in the browser on rows fetched through a keyless proxy. The proxy shares one IP against a per-IP anonymous limit, so a 429 is shown as a 429 with the command to run instead — the CLI is the primary live path, and every reader has their own quota there.

How wide is the window?

The last 800 prints, not 24 hours — 3.6 h on the hero pair, 23 h on Mog. The span is on every row, and the receipt carries the window's share of the pool's 24 h transactions (16% here).

Is a round-trip a verdict on a person?

No. It is a shape: same wallet, same block, opposite sides, size within 5 %. The page prints the rows and the definition, never a label on a person. A router contract can appear as one maker for many users; the number is "the same address on both sides", exactly as the API reports it, and nothing more is claimed.

Why does p90 sit near 60.9 bps on the routed pool?

Quote-to-fill is a realised, fee-inclusive print-to-print move: on a 0.30 % pool two consecutive opposite-side prints straddle the fee twice, so p90 lands near 60 bps on every busy v2 pool. It is used comparatively, across the pools of one token in one window, where that bias is shared — which is also why the rule prefers the 0.05 % tiers when they are deep enough.

Why is a pool marked ×2 or ×3?

The feed carries no pool address, so pools are recovered from (venue, base, quote). Uniswap v3 fee tiers of one pair share that key and merge; a row marked ×n is n pools, and its number is per pair, not per tier. Filed as a finding in FEEDBACK.md.

What is not built?

No prediction, no wallet labelling, no composite score, no alerts, no watchlists, no key. The product names the middleman and says where to route; that verb is the whole scope. When no pool clears the routing floor the rule is printed, never widened.
